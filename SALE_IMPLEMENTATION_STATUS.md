# Access-pass implementation and launch gates

Status: unfinished and non-live. Do not accept customer funds. This document describes current implementation evidence, not a production-readiness certification.

Latest verification: `npm run check` passed all 182 tests, TypeScript checking and the frontend build after adding operator reauthorization guards. Normal database updates cannot re-enable an operator without changing their authorization version or restore a version already present in historical votes. Privileged database bypass still requires production role restrictions. The latest separate PostgreSQL harness result was not recovered, so it is not counted as a verified rerun for this change.

## Product and launch decisions

- 4,444 account-bound, database-managed access collectibles. Not native Zcash NFTs, not a trustless on-chain curve.
- First price: 0.02 ZEC. Compounded increase: 0.04444%. Final price: 0.14399274 ZEC. Full-sale total: 279.15557929 ZEC.
- Each price is rounded upward to a zatoshi from the original rational curve, not from a previously rounded price.
- Confirmed custodial ZEC credit funds atomic database purchases. No transfer or curve buyback in v1.
- The user has not provisioned PostgreSQL or a Zcash wallet/node provider. Access duration and usage allowance are explicitly deferred.
- No real-money launch or deployment has been performed. Production routes use the default hard launch lock in `runtime.ts`; environment variables alone cannot remove it.

### Settlement details and trust boundaries

The scanner uses node block transaction IDs plus Zallet `z_viewtransaction`, not `z_listtransactions`: the latter failed on a non-UTF-8 coinbase memo in the pinned beta.3 integration. Treasury self-funding and coinbase cannot create customer credit. Unknown or malformed responses retain the checkpoint.

The wallet signer creates its own PCZT, verifies recipient/amount/fee/privacy metadata, checks proposal consistency after proving, requires complete signatures, extracts without broadcasting, and binds the reported txid through the wallet decoder. Inspection metadata is not independent proof of change ownership; the configured treasury wallet is trusted. No externally supplied PCZT is accepted.

Signed bytes are persisted before broadcast and replayed exactly. Missing artifacts after a signing claim require review, never automatic re-signing. PostgreSQL byte hashing detects corruption but does not validate transaction semantics. Production role restrictions and manual recovery remain necessary.

RPC transport is server-only: HTTPS or loopback HTTP, explicit method lists, Basic authentication outside URLs, bounded requests/responses, timeout, no redirects, response-ID checking, and redacted provider errors. Credentials must never enter frontend environment variables.
